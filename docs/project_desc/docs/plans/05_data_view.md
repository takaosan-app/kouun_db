# 開発計画書 02.5：データ確認Viewer編

版：v0.1／更新日：2026-09-14  
到達目標：収集した観測所・観測値・品質・取込状況を、開発者がブラウザから安全に確認できるようにする。

## 1. Viewerの位置付け

本Viewerは、収集・DB構築中にデータ内容を確認するための開発・管理用画面とする。

将来利用者へ提供するFlutterアプリとは分離する。Viewerで画面やデータの見せ方を試せるが、その実装をそのまま本番アプリの仕様とは扱わない。

```text
PostgreSQL＋PostGIS
        ↓ 読み取り専用接続
Streamlit Viewer
        ↓
開発者がブラウザで確認

将来：
PostgreSQL＋PostGIS
        ↓
FastAPI
        ↓
Flutter Web／Android／iPhone
```

全国データの収集完了を待たず、静岡県の少数地点と既存データでViewerを構築する。

## 2. 基本方針

| 項目 | 採用方針 |
|---|---|
| 用途 | 開発・管理用のデータ確認 |
| UI | Python＋Streamlit |
| DB | 既存のPostgreSQL＋PostGIS |
| DB権限 | 読み取り権限を持つanalyzerユーザー |
| 実行環境 | Docker Composeの独立したviewerサービス |
| Pythonイメージ | 初期はcollector・analyzerと共通 |
| 公開範囲 | 初期はホストの`127.0.0.1`のみ |
| 接続方法 | VS Codeのポート転送またはSSHポートフォワード |
| 外部通信 | Viewerサービスからの外部通信は原則不要 |
| 本番利用 | 初期対象外。外部公開や複数利用者向けには使用しない |

Viewerから観測値、観測所、取込結果を更新しない。データ修正や再取込はcollector側の処理として実行する。

## 3. 初期画面

### 3.1 DB概要

以下をカードまたは一覧で表示する。

- DB全体のサイズ
- `weather`スキーマの概算サイズ
- 論理観測所数
- 観測所履歴行数
- 観測値数
- 原本ファイル数
- 取込実行数
- 最終取込日時
- 最終成功日時
- 失敗中または直近失敗した取込

件数だけで正常と断定せず、対象期間や最終成功日時も併記する。

### 3.2 観測所一覧

以下を表示する。

- 観測所名
- 都道府県
- 内部の`station_key`
- 気象庁公式観測所番号
- 過去データ・ダウンロード用ID
- 緯度・経度
- 標高
- 観測所種別
- 現行・終了済み
- 取得可能項目コード
- 取得可能カテゴリ
- 情報取得日時

観測所の位置を地図上にも表示する。

同じ論理観測所に構成別の複数行がある場合、一覧では原則1観測所として表示し、詳細表示で構成別位置を確認できるようにする。

終了済み観測所と現行観測所を区別する。名称が同じという理由だけで同一観測所として表示しない。

### 3.3 観測データ

利用者が次を選択できるようにする。

- 観測所
- 観測項目
- 開始日
- 終了日
- 品質状態

結果は時系列グラフと表の両方で表示する。

表には次を含める。

- 対象日
- 観測項目
- 数値または文章値
- 単位
- 品質状態
- 気象庁品質コード
- 現象なし情報
- 均質番号
- 原本ファイル
- 取得日時

数値項目、風向、天気概況を同じグラフへ無理に描画しない。

## 4. 品質・欠測の表示

以下を区別する。

- 正常値
- 利用上注意が必要な値
- 欠測
- 未観測
- 観測対象外
- 未取得
- 取得失敗

値がない箇所をゼロとして表示しない。時系列グラフでは欠けた箇所を空白または途切れとして表示する。

`questionable`は気象庁の品質情報を表す。将来こちらで検出する`anomaly`とは別の状態として表示する。

近隣観測所の値を農地そのものの実測値として表示しない。

## 5. 収集状況

取込履歴画面では次を表示する。

- 取込実行ID
- 提供元
- 原本ファイル
- 開始日時
- 終了日時
- 状態
- 解析件数
- 追加件数
- 更新件数
- 未変更件数
- 訂正履歴件数
- エラーメッセージ

原本ファイルについて次を確認できるようにする。

- 保存パス
- SHA-256
- バイト数
- 取得日時
- 対象期間
- 文字コード
- Content-Type
- collector版
- リクエスト条件

初期画面では概要に最終状態だけを表示し、詳細な収集状況画面は次段階で追加する。

## 7. ソース構成

初期構成は次を基本とする。

```text
src/
└── viewer/
    ├── __init__.py
    ├── app.py
    ├── database.py
    ├── overview.py
    ├── stations.py
    └── observations.py
```

各ファイルの責務は次のとおり。

| ファイル | 責務 |
|---|---|
| `app.py` | Streamlitの画面構成とページ切替 |
| `database.py` | 読み取り専用DB接続 |
| `overview.py` | DB概要と取込状態の取得・表示 |
| `stations.py` | 観測所一覧、能力、地図 |
| `observations.py` | 観測値の検索、表、グラフ |

1ファイル250行を構成見直しの目安とする。行数を減らすためだけの分割は行わず、SQL、表示、接続等の責務で分ける。

## 8. Docker Compose

`viewer`サービスを追加する。

初期仕様は次のとおり。

- Streamlitをポート8501で起動
- ホスト側は`127.0.0.1:8501`へバインド
- DBのhealthcheck完了後に起動
- `backend`ネットワークのみに接続
- DB接続にはanalyzerユーザーを使用
- `collector_egress`には接続しない
- 初期は既存Pythonイメージを共有

Viewerの機能が増え、依存関係やイメージサイズが収集処理へ影響する場合は、Viewer専用Dockerfileと依存ロックへ分離する。

## 9. セキュリティ

初期Viewerは外部公開しない。

- PostgreSQLのポートを外部公開しない
- Viewerのポートは`127.0.0.1`だけに公開
- DBパスワードをコードへ記載しない
- `.env`のanalyzer接続情報を使用
- SQLはパラメーター化する
- ViewerからINSERT、UPDATE、DELETEを実行しない
- 任意SQL入力機能を設けない
- 大量検索を防ぐ期間・件数上限を設ける

LANやインターネットへ公開する場合は、認証、HTTPS、アクセス制御、ログ、更新方針を別途設計する。

## 10. 開発順序

| 段階 | 実装内容 | 完了条件 |
|---|---|---|
| V0 | Streamlit依存追加、viewerサービス、DB接続 | ブラウザから読み取り専用でDBへ接続できる |
| V1 | DB概要 | 件数、容量、最終取込状態が表示される |
| V2 | 観測所一覧・地図 | 静岡県31地点と取得可能項目を確認できる |
| V3 | 観測データ | 静岡の期間・項目選択、グラフ、品質付き表を確認できる |
| V4 | 収集状況詳細 | 成功・失敗・原本・訂正履歴を追跡できる |
| V5 | 分析結果 | 集計・比較・異常値候補の実装後に表示を追加する |

まずV0～V3を実装する。V4以降は収集・分析機能の進捗に合わせる。

## 11. Webhook通知との接点

Viewerは通知処理を直接実行しない。

将来は次の構成とする。

```text
collector／analyzer
        ↓
異常候補または実行失敗をDBへ記録
        ├── Viewerで表示
        └── notifierがWebhook送信
```

通知候補は次のとおり。

- 収集バッチ失敗
- 長期間の欠測
- 気象庁が利用上注意とした値
- 訂正値の取得
- 分析処理が登録した異常値候補

Webhook URLは環境変数または秘密情報管理へ保存し、コード・DB・計画書には記載しない。同じイベントの重複通知を防ぐ識別子と送信履歴を保持する。

統計的な異常値通知は、3年分データによる候補確認と誤検出評価の後に有効化する。

## 12. 初期完了条件

以下をすべて満たしたらV0～V3を完了とする。

- `docker compose`でViewerを起動できる
- ブラウザから`127.0.0.1:8501`へ接続できる
- ViewerがanalyzerユーザーでDBへ接続する
- ViewerからDBを更新できない
- DB件数と容量を表示できる
- 静岡県31観測所を一覧と地図で表示できる
- 観測所のダウンロードIDと取得可能項目を表示できる
- 静岡の観測値を期間・項目で検索できる
- 数値をグラフと表で確認できる
- 欠測とゼロを区別できる
- 品質状態と出典を確認できる
- データがない場合に例外画面ではなく理由を表示できる

## 13. 保留事項

- Viewer専用イメージへの分離時期
- LAN内公開の必要性
- 認証の追加
- 地図表示ライブラリの変更
- 分析結果・異常値候補の表示
- Webhook通知先
- Viewerから再取込を起動する管理機能

再取込や収集開始などの更新操作は、読み取り専用Viewerの初期範囲に含めない。
