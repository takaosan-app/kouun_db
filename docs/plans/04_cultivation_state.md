# 開発計画書 04：栽培イベント・状態管理編

版：v0.6／更新日：2026-09-21  
状態：初期設計案（DB設計前）  
到達目標：圃場ごとの栽培履歴をイベントとして記録し、そこから現在の栽培状態を再現可能に導出する。

## 1. この文書の目的

圃場ごとの栽培履歴をイベントとして記録し、その履歴から現在の栽培状態を導出するための
仕様を整理する。最初の対象は、いちごと水稲とする。

本書は農業上の概念と画面入力の仕様を定める文書であり、テーブルや型を確定するDB設計書
ではない。分析全体の目的、気象データの使い方、リスク判定の考え方は
[03_data_analysis.md](03_data_analysis.md)を参照する。ここで導出した栽培状態が、
L3のリスク判定の入力になる。

## 2. 基本方針

### 2.1 管理単位

```text
農場
└─ 圃場・ハウス
   └─ 栽培案件（作期）
      └─ 栽培イベント履歴
```

この栽培案件が、分析の基本単位でもある。L3のリスク判定は栽培案件×日で計算する。

- 同じ圃場でも、年または作期が異なれば別の栽培案件とする
- 初期版は、1圃場につき同時期に1つの栽培案件を基本とする
- 同じ圃場内の区画、複数品種、複数作型への分割は後続機能とする

### 2.2 イベントを正本とする

現在状態を利用者が直接選択して上書きする方式にはしない。実際に発生した出来事を
イベントとして保存し、日付順に適用して現在状態を導出する。

```text
イベント履歴 + 対象日 → 生育状態・場所・処理状態
```

イベントを訂正または取り消した場合は、そのイベントの日付以降を再計算する。

### 2.3 状態を一つの値に詰め込まない

いちごの「育苗中」と「苗場にある」は異なる性質である。状態は少なくとも次の軸に分ける。

| 状態軸 | 意味 | 例 |
|---|---|---|
| 生育段階 | 作物の生物学的な段階 | 育苗中、開花期、収穫期 |
| 所在・栽培場所 | 作物が管理されている場所 | 苗場、本圃、冷蔵設備 |
| 処理状態 | 特別な管理処理の有無 | 冷蔵処理中、通常管理 |
| 案件状態 | 栽培案件全体の状態 | 予定、進行中、終了、中止 |

これにより「本圃で育苗中」「苗場で育苗中」「冷蔵設備で処理中」を同じ育苗段階の派生として
扱える。

## 3. 記録するイベントの共通項目

| 項目 | 必須 | 内容 |
|---|---:|---|
| 栽培案件 | 必須 | どの作期の出来事か |
| イベント種別 | 必須 | 定植、開花開始など |
| 発生日 | 必須 | 原則として圃場の現地日付 |
| 発生時刻 | 任意 | 日単位で足りない場合のみ使用 |
| 記録方法 | 必須 | 手入力、日誌から確認、外部連携など |
| 詳細 | 任意 | 温度、場所、処理方式などの構造化情報 |
| メモ | 任意 | 自由記述 |
| 登録者・登録日時 | 必須 | 監査と訂正履歴のために保持 |

実績イベントとシステムによる推定は分離する。確定した栽培履歴には、利用者が確認した実績
のみを保存する。推定日は分析結果として保持し、利用者が確認した時点で実績イベントへ変換する。

## 4. 共通イベント

| イベント | 用途 | 主な入力 | 状態への影響 |
|---|---|---|---|
| 栽培開始 | 作期を開始する | 開始日、品目、品種 | 案件を進行中にする |
| 栽培終了 | 通常の作期を終了する | 終了日 | 案件を終了にする |
| 栽培中止 | 途中で打ち切る | 中止日、理由 | 案件を中止にする |
| 病害確認 | 病気の発生を記録する | 病名、不明可、程度、メモ | 生育状態は変えない |
| 害虫確認 | 害虫の発生を記録する | 害虫名、不明可、程度、メモ | 生育状態は変えない |
| 作業記録 | 防除・施肥等を記録する | 作業区分、メモ | 原則として状態は変えない |

病害虫確認と作業記録は複数回登録できる。状態遷移イベントと観察・作業イベントを区別する。

## 5. いちご

### 5.1 初期登録

| 項目 | 必須 | 備考 |
|---|---:|---|
| 圃場またはハウス | 必須 | 栽培案件の所属先 |
| 品種 | 任意 | 不明を許容する |
| 育苗開始日 | 必須 | 栽培開始イベントの日付にもなる |
| 育苗場所 | 必須 | 本圃または苗場 |

冷蔵処理の有無、本圃定植日、開花日、収穫日は、初回登録時には要求しない。該当時期に
なったら追加する。

### 5.2 イベント定義

| イベントコード案 | 画面表示 | 必須入力 | 任意入力 | 主な状態変化 |
|---|---|---|---|---|
| `nursery_started` | 育苗開始 | 日付、育苗場所 | 品種、メモ | 育苗中になる |
| `cold_treatment_started` | 冷蔵処理開始 | 日付 | 方式、設定温度、明暗、メモ | 冷蔵処理中になる |
| `cold_treatment_ended` | 冷蔵処理終了 | 日付 | 実測温度、メモ | 冷蔵処理を終了する |
| `transplanted` | 本圃へ定植 | 日付、本圃 | 株数、メモ | 所在を本圃にする |
| `flower_bud_confirmed` | 花芽分化確認 | 日付 | 確認方法、メモ | 花芽分化確認済みにする |
| `flowering_started` | 開花開始 | 日付 | 花房、メモ | 開花期にする |
| `harvest_started` | 収穫開始 | 日付 | メモ | 収穫期にする |
| `harvest_ended` | 収穫終了 | 日付 | メモ | 栽培を終了する |

花房は初期版では任意とし、最初の開花開始のみで状態を変更する。花房ごとの繰り返し管理は
必要性を確認してから追加する。

### 5.3 導出する状態

| 生育状態 | 所在・処理の例 | 開始条件 | 終了条件 |
|---|---|---|---|
| 育苗中 | 本圃 | 本圃を指定した育苗開始 | 開花開始、収穫開始、終了 |
| 育苗中 | 苗場 | 苗場を指定した育苗開始 | 本圃定植、終了 |
| 育苗中 | 冷蔵設備・冷蔵処理中 | 冷蔵処理開始 | 冷蔵処理終了 |
| 定植待ち | 苗場等・通常管理 | 苗場で冷蔵処理終了 | 本圃定植 |
| 定植後 | 本圃 | 本圃定植 | 開花開始、収穫開始、終了 |
| 開花期 | 本圃 | 開花開始 | 収穫開始、終了 |
| 収穫期 | 本圃 | 収穫開始 | 収穫終了 |
| 栽培終了 | 最終所在地 | 収穫終了または栽培終了 | なし |

「本圃で育苗開始」の経路には本圃定植イベントを要求しない。花芽分化確認は重要な観察結果
だが、未入力でも後続イベントを登録できるようにする。

### 5.4 代表的な遷移

```text
本圃開始
  育苗中（本圃） → 開花期 → 収穫期 → 栽培終了

苗場開始
  育苗中（苗場） → 本圃・定植後 → 開花期 → 収穫期 → 栽培終了

苗場・冷蔵あり
  育苗中（苗場） → 冷蔵処理中 → 定植待ち → 本圃・定植後
                  → 開花期 → 収穫期 → 栽培終了
```

### 6.1 初期登録

| 項目 | 必須 | 備考 |

| 圃場 | 必須 | 水田を選択する |
| 品種 | 任意 | 不明を許容する |

|---|---|---|---|---|

分げつ、幼穂形成、登熟は初期版では任意入力とする。未入力の場合は経過日数や積算温度から
推定状態を表示できるが、確定履歴にはしない。

### 6.3 導出する状態

| 生育状態 | 開始条件 | 終了条件 |
|---|---|---|
| 播種後 | 播種または直播 | 育苗開始、移植、分げつ確認 |
| 育苗中 | 育苗開始 | 移植 |
| 本田・移植後 | 移植 | 分げつ確認、幼穂形成確認、出穂開始 |
| 本田・直播後 | 直播 | 分げつ確認、幼穂形成確認、出穂開始 |
| 分げつ期 | 分げつ確認 | 幼穂形成確認、出穂開始 |
| 幼穂形成期 | 幼穂形成確認 | 出穂開始 |
| 出穂期 | 出穂開始 | 登熟開始、収穫開始 |
| 登熟期 | 登熟開始 | 収穫開始 |
| 収穫中 | 収穫開始 | 収穫終了 |
| 栽培終了 | 収穫終了または栽培終了 | なし |

### 6.4 代表的な遷移

```text
移植栽培
  播種後 → 育苗中 → 本田・移植後 → 分げつ期 → 幼穂形成期
         → 出穂期 → 登熟期 → 収穫中 → 栽培終了

直播栽培
  本田・直播後 → 分げつ期 → 幼穂形成期 → 出穂期
               → 登熟期 → 収穫中 → 栽培終了
```

任意イベントが省略された場合も、次の実績イベントへ進める。例えば移植の次が出穂開始でも
有効な履歴として扱う。

## 7. 入力順序と検証

### 7.1 原則

農作業は後日まとめて入力されることがあるため、登録順と発生日順は一致しない。通常と異なる
順序を直ちに拒否せず、次の3段階で扱う。

| 判定 | 処理 | 例 |
|---|---|---|
| 正常 | そのまま登録 | 開花開始後に収穫開始 |
| 要確認 | 警告して登録可能 | 花芽分化確認なしで開花開始 |
| 登録不可 | 矛盾を解消するまで保存しない | 終了日が開始日より前、対象案件が異なる |

### 7.2 主な警告規則

| 作物 | 条件 | 表示する警告 |
|---|---|---|
| 共通 | 栽培終了後の日付に新しい生育イベント | 終了日またはイベント日を確認する |
| 共通 | 同じ種類・同じ日付のイベントが存在 | 重複登録か確認する |
| いちご | 冷蔵開始が育苗開始より前 | 日付を確認する |
| いちご | 冷蔵終了なしで本圃定植 | 冷蔵終了日の記録漏れか確認する |
| いちご | 苗場開始だが定植なしで開花開始 | 本圃定植の記録漏れか確認する |
| 水稲 | 移植栽培だが移植なしで出穂開始 | 移植日の記録漏れか確認する |
| 水稲 | 直播栽培に移植を登録 | 栽培方法を確認する |
| 水稲 | 収穫開始が出穂開始より前 | 日付を確認する |

警告規則には版を付ける。規則変更によって過去のイベント自体を書き換えない。

## 8. 訂正・取消・履歴

- 利用者による日付や詳細の訂正を許可する
- 監査のため、訂正前の内容と訂正者・訂正日時を追跡できるようにする
- 誤登録は物理削除せず、取消状態として扱う
- 状態計算では取消済みイベントを除外する
- 訂正または取消が発生した最古の日を`recalc_from`として、その日以降の分析を再計算する
- 同じ日に複数イベントがある場合は、イベント種別ごとの優先順位で決定的に処理する

同日内の詳細な順序が分析に影響することが分かった場合に限り、発生時刻または明示的な
並び順を必須化する。

## 9. 推定状態の扱い

実績と推定を画面上で明確に区別する。

```text
現在状態：開花期（9月18日に本人が確認）
予測：収穫開始まで約25日（気温実績と平年値から算出）
```

- 実績状態は確定イベントから導出する
- 推定状態・推定日は分析結果として計算する
- 推定の根拠、使用した気象系列、ルールの版、計算日時を保持する
- 新しい実績イベントが入ったら、それ以前の推定より実績を優先する
- 利用者が推定を確認した場合だけ、実績イベントとして登録する
- 推定状態しかない場合は、その旨と不確実性を画面へ表示する

## 10. 記録入力の方針

### 10.1 日誌を主入力とする

旧版ではイベントごとのワンタップ登録を主とした。これを改め、日誌を主入力とする。

理由は、問いかけへの回答は「答えさせられる」ため継続しないが、日誌は農家が自分のために
書くため継続する動機が本人の側にあるためである。栽培日誌は農業の現場に元からある習慣で
あり、新しい行動を要求しない。

### 10.2 天気はチェック方式

自由記述からの降雨判定は、否定・予測・過去参照が混在するため信頼性が低い
（「雨が降りそう」「雨が降らなくて困る」等）。天気は構造化入力とする。

```text
今日の天気   [晴] [曇] [雨] [雪]        ← 複数選択
```

単一選択にすると「晴れのち雨」で情報が落ちるため、複数選択とする。判定側は雨が
含まれていれば降雨日として扱う。

閾値の表示は仕様値ではなく体感で書く。

```text
✕ 雨（1mm以上）
◯ 雨（地面が濡れた）
```

「地面が濡れた」はおおむね1mm前後に対応し、メッシュデータのOPR（1mm以上の降水の有無）と
同じ閾値となる。同一のスロットに入れて相互に検証・代替できる。利用者の記入がない日は
OPRまたは観測所値で埋める。

チェック項目の文言と閾値定義は版を付けて保存する。文言を変更すると過去データの意味が
変わるため、判定ルールと同様に扱う。

### 10.3 自由記述は蓄積のみ

自由記述欄は任意とし、空でも保存できるようにする。

```text
天気チェック  今日の判定に使う（構造化・確実）
自由記述      将来の検証に使う（任意）
```

病害虫が発生した際の記述（「葉に黒い斑点」等）は、数年後の検証データとして価値がある。
ただし当面は蓄積のみとし、LLM等による抽出処理は行わない。必要になった時点で遡って
処理すればよい。

### 10.4 イベント登録は補助とする

日誌から栽培イベント（定植、開花、収穫、病害虫確認）を抽出できるため、ワンタップ登録の
ボタンは補助的な位置づけとする。ただし主要イベントの日付は分析の基準日になるため、
日誌とは別に確定値として保持する。

```text
[今日、冷蔵を開始]
[今日、本圃へ定植]
[今日、開花を確認]
[今日、収穫を開始]
[病害虫を確認]
```

積算温度等から開花時期が近いと推定した場合は「花が咲き始めましたか」と確認を促す。
回答がなければ推定状態として扱う。

### 10.5 初回の必須入力

- 圃場またはハウス
- 品種（不明も許容）
- 栽培開始日
- 育苗場所：本圃または苗場（いちごの場合）

苗場を選んだ場合だけ、冷蔵処理の有無と本圃定植日を後から入力する。冷蔵処理ありの場合
だけ開始日・終了日を表示する。すべてを栽培開始時に入力させない。

## 11. 最小画面フロー

### 11.1 栽培開始

1. 圃場を選ぶ
2. 品目を選ぶ
3. 品種を選ぶ（不明可）
4. 開始日を入力する
5. 品目固有の最小項目だけ入力する
6. 栽培案件を開始する

いちごでは育苗場所、水稲では栽培方法を品目固有の必須項目とする。

### 11.2 日々の利用

- 現在状態と、その根拠となった最新イベントを表示する
- 今の状態で登録されやすいイベントを上位に表示する
- 「今日」を初期値とし、日付だけ直せるようにする
- 詳細入力は折りたたみ、最小操作で記録できるようにする
- 日誌から候補を抽出した場合も、主要イベントは利用者の確認後に確定する

## 12. DB設計へ渡す要件

次の概念を別々に表現できることをDB設計の要件とする。

| 概念 | 役割 |
|---|---|
| 農場 | 利用者が管理する農場 |
| 圃場・施設 | 栽培場所、位置、施設区分 |
| 栽培案件 | 圃場、作期、品目、品種、栽培方法をまとめる |
| イベント種別 | 品目別イベントの台帳と表示名 |
| 栽培イベント | 実績の発生日と入力内容 |
| イベント訂正履歴 | 訂正前後、取消、操作者を記録する |
| 推定結果 | 推定日、根拠、ルール版、計算日時を保持する |
| 状態スナップショット | 表示高速化用。イベントから再生成可能とする |

対応するテーブルの候補は次のとおり。名称と列はDB設計時に確定する。

| 候補名 | 対応する概念 |
|---|---|
| `farm` | 農場 |
| `field` | 圃場・ハウスと位置、参照する気象系列（要素別・近傍リスト、距離と標高差付き）、施設情報 |
| `cultivation` | 年・作期ごとの品目、品種、開始・終了 |
| `cultivation_event` | 実績または推定イベント |
| `crop_stage_rule` | イベントから状態を導出する規則 |
| `diary_entry` | 日誌。天気チェック、自由記述 |
| `diary_observation` | 日誌から得た構造化観測（降雨の有無等） |
| `input_spec_version` | 入力項目の文言と閾値定義の版 |

気象系列側（`weather_series`、L1・L2）と判定規則側（`risk_rule`、`risk_result`）は
[03_data_analysis.md](03_data_analysis.md)で扱う。

イベント固有の詳細をすべて列にするか、共通列とJSONを併用するかはDB設計時に決定する。
現在状態のスナップショットを保存する場合も正本にはせず、再計算可能なキャッシュとして扱う。

## 13. 初期版の範囲

初期版では次を実装対象とする。

- 圃場と栽培案件の登録
- いちご・水稲の主要な実績イベント登録
- イベントの訂正・取消
- イベント履歴からの現在状態導出
- 要確認となる順序の警告
- 現在状態と根拠イベントの表示

次は初期版に含めない。

- 花房、株、畝ごとの詳細管理
- 複数区画・複数品種の同時管理
- 推定イベントの自動確定
- 病害虫の診断または農作業の自動指示
- 冷蔵方式別の詳細な成育判定
- リスクルールの本実装
